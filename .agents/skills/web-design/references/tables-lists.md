# Tables, Lists and Trees

## Table
Use when users compare values across columns. Keep headers clear; sticky headers are useful for long datasets. Add sorting/filtering only when meaningful.

## List
Use for homogeneous items where scanning one dimension matters more than column comparison. Rows can reveal secondary actions on hover, but actions remain keyboard/touch accessible.

## Tree
Use for hierarchical objects such as files, layers or nested categories. Indentation must communicate depth; expand/collapse state must be explicit.

## Density
Choose comfortable, compact, or dense according to task. High-frequency desktop tools may use 28–36px rows; touch contexts need larger targets.

## Responsive
Do not blindly compress a desktop table. Prioritize columns, enable horizontal scroll when comparison must remain tabular, or transform into structured rows/cards when semantics allow.

## Avoid
Cards for hundreds of records, hidden selection state, row actions available only by hover, ambiguous sortable headers.

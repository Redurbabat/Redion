# Accessibility

## Baseline
Accessibility is a design constraint, not a final patch.

Use semantic HTML, logical heading order, native controls where possible, keyboard operability, visible focus, accessible names, sufficient contrast, and reduced-motion support.

## Keyboard
All interactive functions must be reachable without a pointer. Focus order follows visual/task order. Do not create keyboard traps except intentional modal focus containment.

## Visual
Do not communicate state with color alone. Text and controls must remain legible at zoom. Focus indicators must be visible against surrounding surfaces.

## Forms
Labels associate with controls. Errors identify the field and recovery. Required state is communicated programmatically and visually.

## Dynamic UI
Announce meaningful async updates when needed. Menus, tabs, dialogs, comboboxes and trees should follow established semantic patterns.

## Media
Provide meaningful alt text for informative images; decorative images should not add noise. Captions/transcripts when required by content.

## Motion
Honor reduced motion and avoid flashing or motion that can interfere with use.

# Cards and Content Containers

## Rule
A card represents an independent semantic object or grouped unit. A border and rounded rectangle are not a default layout primitive.

## Choose by content
- Product -> product card when visual comparison matters.
- Article -> article card/row depending density.
- Document -> thumbnail card for recognition; row/list for scale.
- Project -> project card when imagery/outcome matters.
- Person -> profile row/card depending context.
- Metric -> compact metric panel.
- 20–100+ homogeneous records -> list/table, not a giant card grid.
- Form section -> often plain section/divider, not card.

## Interactive cards
Whole-card click is appropriate only when one destination/action dominates. Provide hover, focus-visible and pressed feedback. Nested buttons/links need clear event and focus behavior.

## Static cards
No hover lift or pointer cursor unless interactive.

## Visual treatment
Use padding, radius, border, shadow and background according to density/material system. Dense dashboards usually need tighter padding and flatter surfaces; marketing can use more space and visual storytelling.

## Avoid
Card-inside-card nesting, every section boxed, huge empty padding, decorative badges, fake hover states, excessive glass, identical card proportions for unrelated content.

# Dashboard / Admin Pattern

## Goal
Enable fast monitoring, comparison and action.

## Structure
Persistent navigation -> page identity/actions -> filters/time context -> primary metrics/data -> supporting analysis/details.

## Density
Prefer useful information density. A dashboard is not a marketing page. Use tables/lists when records dominate; metrics should be compact and contextual.

## Interaction
Filters clearly show active state. Preserve filter/sort state when useful. Bulk actions appear with selection. Drill-down should preserve return context.

## Motion
Level 0–1 normally. Avoid animated counters/charts that delay reading.

## Avoid
Huge hero banners, oversized cards, fake metrics, chart decoration without analytical value, every statistic in a separate giant tile.

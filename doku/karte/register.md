## Datenmodell

Vier verschiedene Ablagen, keine gemeinsam. (a) REGISTER liegen nur im RAM: jedes hält `const LISTE = EINGEBAUT.slice()` (bloecke.ts:266, eigenschaften.ts:68, module.ts:133, navigation.ts:412, einstellungen.ts:116, verbindungen.ts:105, tasten.ts:171, formeln.ts:631) bzw. leere Listen (befehle.ts:52-53 lieferanten/feste, menueband.ts:987-988 fremde/lieferanten, context.ts:81-85 LISTE/LIEFERANTEN/stapelQuellen, vorlagen.ts:27). Nichts davon geht in IndexedDB, nichts in eine Sicherung; nach dem Neuladen ist alles weg, was nicht Code ist. Herkunft je Eintrag: bloecke.ts:267 und eigenschaften.ts:72 führen ein `vonAussen: Set<string>` (nur Kennung, kein Name), navigation.ts:427 setzt `vonAussen: true`; alle anderen unterscheiden Eingebautes und Gemeldetes nicht. (b) ERWEITERUNGEN: Fach `meta`, Schlüssel `erweiterungen` (erweiterungen.ts:44-45), eine Liste von `{ name, kurz, code, an }` (Z.395-397 lesen(), Z.432 Einbauen, Z.341 an-Schalter). Kein Manifest, keine Fassung, keine Rechte, keine Signatur, kein Zeitstempel. Was eine Erweiterung angemeldet hat, steht nur im RAM `angemeldet` (Z.49-55) mit `von: name`. (c) AUTOMATIONEN: Daten IM Datenbankobjekt, Fach `collections`, Feld `coll.automationen[]` (steuerung.ts:7989 `Store.updateCollection(coll.id, { automationen })`, 8765); ein Eintrag hat `an`, `wenn {art, key, wert}`, `weitereWenn[]`, `wennModus ('alle')`, `bedingungen[]`, `sonst[]` (Z.8049-8170, 7741); Aktionsarten und Auslöserarten sind Code-Listen (Z.7567, 7792), keine Registerobjekte. Der Laufverlauf steht im Protokoll: Fach `meta`, Schlüssel `protokoll`, höchstens 2000 Einträge (protokoll.ts:42-43), Art 'automation' (Z.55, steuerung.ts:8181). Knopf-Block: Fach `blocks`, Felder `aktionen[]` bzw. `aktion`, `bestaetigen` (editor.ts:2326-2332). (d) AUFTRÄGE: Fach `auftraege` über `Store.auftragPut` (maschine.ts:288), Form aus `JobModell.anlegen(id, art, eingabe, jetzt, zeitText, {schritte, maxVersuche, text, bedingung})` (Z.286-287); die Läufer selbst nur im RAM `werkzeuge: Map<string, Werkzeug>` (Z.97). (e) BUS: Zuhörer `Map<string, Set>` und letzte Meldung je Name `gemeldet` (bus.ts:60, 67) — RAM je Tab. (f) MCP: Fach `meta`, `mcp:server` und `mcp:freigabe` (werkzeuge.ts:51-54). (g) EINSTELLUNGEN: Fach `meta`, Schlüssel = `id` des Registereintrags (einstellungen.ts:136 `Store.getMeta(id, e.vorgabe)`, 157 `Store.setMeta(id, wert)`).

## Risiken

- Sicherheit (§19/§47, L30): Erweiterungscode läuft im selben Ursprung per new Function (erweiterungen.ts:166); ABGESCHIRMT (Z.154-158) ist eine Parameterliste, kein Ursprungswechsel — `eval` fehlt darin ausdrücklich (Z.159-160). Eine gemeinsame Schicht, die mehr Rechte durchreicht (z. B. Ereignisbus, Register.bloecke.melde), vergrössert diesen Zaun, bevor es ein Rechtemodell gibt.
- Datenherkunft: Redion.schreibe.block/seite/zeile schreiben über Store.addBlock/addRow (Z.115-131) ohne Vermerk, dass eine Erweiterung schrieb — `erstelltVon` bleibt der Nutzer (indexdb.ts addBlock). §21 verlangt für KI „rückgängig, versioniert, löschbar“; für Erweiterungen gilt heute nur das, was der Verlauf-Monkeypatch zufällig mitnimmt (verlauf.ts:97-103). Ein Manifest müsste die Herkunft in die Daten schreiben — das ist eine Feldergänzung im Fach blocks, also Migration mit Prüflauf (§9).
- Lebenszyklus heute falsch: `beimStart` läuft bei JEDEM alleLaufen (erweiterungen.ts:86; alleLaufen aus Toggle Z.342, Entfernen Z.351, Probelauf Z.417, Einbauen Z.434) — ein Start-Hook, der Seiten anlegt, legt sie mehrfach an. `beiAenderung` feuert nur, wenn start() bis Store.on kam (Z.448); start() steigt bei leerer Liste vor Store.on aus (Z.446) — eine erst nach dem Start eingebaute Erweiterung hört bis zum Neuladen nichts. Eine gemeinsame Schicht muss beides zuerst reparieren, sonst erbt sie es.
- Abschalten ist unvollständig: `zuruecksetzen()` (Z.57-62) leert nur die vier RAM-Listen; Formula.F behält die Funktionen (Z.179-182 schreibt, niemand löscht), Store.on-Horcher bleibt registriert (kein off). Sieben Register haben kein nimmZurueck (ansichten.ts:66, einstellungen.ts:169, formeln.ts:686, tasten.ts:235, vorlagen.ts:90, verbindungen.ts:132, elektroformeln.ts:5085) — ein Plugin, das dort meldet, ist bis zum Neuladen nicht rückholbar.
- Herkunft im Register: nur bloecke/eigenschaften merken `vonAussen` als Set von Kennungen (bloecke.ts:267, eigenschaften.ts:72), navigation als Flag (Z.427). Kein Register weiss, WELCHE Erweiterung einen Eintrag machte — ein Rücknahme-Manifest kann heute nichts zuordnen. Ein Feld `von` an jedem melde() ist Voraussetzung, keine Nebensache.
- Blocktypen aus Erweiterungen: Register.bloecke.alle() ist bewusst EINE Liste, die der Editor beim Laden festhält (bloecke.ts:222-225, editor.ts:41). Wird ein Blocktyp abgemeldet, bleiben Blöcke dieses Typs Daten (§18: nicht löschen) und fallen im Editor auf default (Textfeld, editor.ts:985). Import/Export tragen den Typ mit — ein Plugin-Manifest darf keine Typ-Umbenennung bei Deaktivierung machen.
- Automationen sind keine Registerobjekte: Auslöser- und Aktionsarten sind Code-Listen in steuerung.ts (7567, 7792); eine Aktionsart von aussen anzumelden gibt es nicht. Sie liegen in coll.automationen im Fach collections und reisen mit .redion/.json — eine Erweiterung, die Automationen schreibt, schreibt Nutzerdaten; ein Import mit unbekannter Aktionsart muss den Eintrag behalten, nicht verwerfen (§17 „alle Typen berücksichtigen“). Ob automationenLaufen unbekannte d.art still übergeht, ist nicht geprüft (nicht gemessen).
- Vier Änderungs-Hooks mit vier Reihenfolgen: Store.on (indexdb.ts:56) plus drei Monkeypatches (verlauf.ts:97-103, protokoll.ts:178-187, steuerung.ts:8812-8813). Wer eine gemeinsame Hook-Schicht einzieht, ändert die Reihenfolge, in der Verlauf-Schnappschuss, Protokolleintrag und Automation zu einer Schreibung laufen — der Schleifenschutz (E86, steuerung.ts:8049ff) und die Pacht (maschine.ts:48-57) hängen an heutigem Timing (setTimeout 0 in Z.8828). Zwei-Tab-Fall (§16): Register und Erweiterungsanmeldungen sind RAM je Tab; ob ein anderer Tab Änderungen an meta 'erweiterungen' nachlädt, wurde nicht gefunden (kein Horcher gesucht/gefunden).
